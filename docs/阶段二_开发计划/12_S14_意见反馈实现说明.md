# S14：意见反馈 — 实现说明

## 文档信息

- **切片 ID**：S14
- **用户结果**：当前在社成员提交反馈并查看本人历史；负责人查看和处理本人负责社团反馈
- **依赖**：S07
- **状态**：已验收

## 实现范围

### 新增模型

| 模型 | 表名 | 说明 |
|---|---|---|
| `Feedback` | `feedback` | 意见反馈：关联提交人、社团，反馈内容、提交时间、状态、可选处理说明 |

**字段设计：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `BigAutoField` | 主键 |
| `submitter` | `FK → User` | 提交人，`PROTECT`，`db_column="submitter_id"` |
| `club` | `FK → Club` | 所属社团，`PROTECT`，`db_column="club_id"` |
| `content` | `TextField` | 反馈内容（必填） |
| `submitted_at` | `DateTimeField(auto_now_add=True)` | 提交时间 |
| `status` | `CharField(max_length=10, choices)` | `待处理` / `已处理`，默认 `待处理` |
| `processing_note` | `TextField(null=True, blank=True)` | 处理说明（可选） |

**约束与索引：**

- `submitter_id` 普通索引（`fb_submitter_idx`）
- `(club_id, status, submitted_at)` 复合索引（`fb_club_status_time_idx`），支持负责人筛选
- 不关联 `ClubMembership`（同一成员可多次提交反馈，与评价的单次约束不同）
- 不保存处理人、处理时间（按阶段一设计）
- 不生成通知（按阶段一设计）
- 管理员无权访问任何反馈接口

| 接口 | 调用者 | 说明 |
|---|---|---|
| `POST /api/clubs/{club_id}/feedback` | 在社成员 | 提交反馈，只需 `content` |

| `GET /api/leader/clubs/{club_id}/feedback` | 负责人 | 分页查看本人负责社团的全部反馈 |
| `POST /api/leader/feedback/{feedback_id}/process` | 负责人 | 处理反馈，`processing_note` 可选 |

## 关键实现决策

### 1. 反馈不关联 membership

与评价（`ClubEvaluation` 使用 `OneToOneField` 关联 `ClubMembership`）不同，反馈允许同一成员对同一社团多次提交。因此 `Feedback` 直接关联 `User` 和 `Club`，不经过 `ClubMembership`。成员资格的校验在视图守卫 `require_club_member` 中完成。

### 2. 处理说明可选且可为 null

`processing_note` 字段 `null=True, blank=True`：负责人可以不填处理说明直接处理，空字符串和未提供均最终存为 `null`。已处理的反馈在表格中显示"—"（空）以示区分。

### 3. 状态单向流转

`待处理 → 已处理` 为唯一允许的状态变更，v1 不支持重新打开（即已处理不能再回到待处理）。重复处理返回 `FEEDBACK_ALREADY_PROCESSED`（409）。

### 4. 提交反馈后不展示历史

与评价卡片（在社团详情页展示本人对该社团的已有评价）不同，反馈卡片仅提供提交入口和引导文字（"欢迎向社团提交反馈建议，你可以在「我的反馈」中查看处理进度"），不在此处加载历史列表。

### 5. 负责人使用分页表格

反馈管理卡片使用 `el-table` + `el-pagination` 展示，因为一个社团可能积累较多反馈。与评价的 `GET /api/me/evaluations`（不分页）不同，负责人接口使用标准 `page`/`page_size` 分页。

### 6. 管理员完全无权限

阶段一设计明确禁止系统管理员查看或处理反馈。因此 S14 不提供 `GET /api/admin/feedback` 接口和对应的管理员页面。管理员的 `FORBIDDEN` 拒绝由 `require_active_student` / `require_leader_of_club` 中的角色校验实现。

## 错误码

| 错误码 | HTTP 状态 | 场景 |
|---|---|---|
| `INVALID_REQUEST` | 400 | `content` 缺失、为空、非字符串，或提交不允许的字段 |
| `NOT_CLUB_MEMBER` | 403 | 非社团成员提交 |
| `MEMBERSHIP_INACTIVE` | 403 | 已退出或已移除的成员提交 |
| `CLUB_CANCELLED` | 409 | 社团已注销（提交或处理） |
| `NOT_CLUB_LEADER` | 403 | 非负责人查看或处理反馈 |
| `FEEDBACK_ALREADY_PROCESSED` | 409 | 重复处理已处理的反馈 |
| `RESOURCE_NOT_FOUND` | 404 | 反馈 ID 不存在 |
