# S16：内容逻辑删除和管理员内容管理 — 实现说明

## 文档信息

- **切片 ID**：S16
- **用户结果**：作者、负责人和管理员按各自权限逻辑删除帖子或回复；管理员查看全部正常及已删除内容
- **依赖**：S11
- **状态**：已验收

## 实现范围

### 新增模型

无。Post 和 Reply 模型在 S10/S11 已包含 `status` 字段（`NORMAL = "正常"` / `DELETED = "已删除"`），逻辑删除只需更新此字段，无需新增数据表或迁移。

### 现有模型利用

| 模型 | 用途 |
|---|---|
| `Post` | `status` 字段已含 `NORMAL`/`DELETED` 两种状态；删除时更新为 `DELETED` |
| `Reply` | 同上 |
| `ClubMembership` | 校验作者的内部权限（`member_status=active`）和负责人身份（`club_role=leader`） |
| `Club` | 校验社团状态（`status=ACTIVE`） |

### 新增接口（4 个）

| 接口 | 调用者 | 说明 |
|---|---|---|
| `DELETE /api/posts/{post_id}` | 作者 / 负责人 / 管理员 | 按三级权限逻辑删除帖子，返回 `{id, status}` |
| `DELETE /api/replies/{reply_id}` | 作者 / 负责人 / 管理员 | 按三级权限逻辑删除回复，含父帖已删除保护 |
| `GET /api/admin/posts` | 系统管理员 | 分页查看全部帖子（含已删除），按 `-id` 倒序 |
| `GET /api/admin/replies` | 系统管理员 | 分页查看全部回复（含已删除），按 `-id` 倒序 |

**接口约束**：`DELETE /api/posts/{post_id}` 复用现有的 `GET /api/posts/{post_id}` 路径，原 `post_detail` 改为 `post_detail_or_delete` 方法分发（GET → post_detail，DELETE → _delete_post）。

## 关键实现决策

### 1. 不新增数据库迁移

Post 和 Reply 模型在 S10/S11 建立时已包含 `status` 字段：

```python
class Status(models.TextChoices):
    NORMAL = "正常", "正常"
    DELETED = "已删除", "已删除"
```

与 Announcement 模型的设计完全一致。S16 只需在视图层将 `status` 设置为 `DELETED` 并保存，无需任何迁移。

### 2. 三级权限路径

每个删除接口按以下优先级逐级尝试授权：

```
管理员 → 作者（含内部权限校验） → 负责人 → FORBIDDEN
```

**管理员**独立于成员关系，可删除任意内容的帖子/回复。

**作者**路径额外校验：
- `ClubMembership.member_status == ACTIVE`（已退出或已移除拒绝）
- `Club.status == ACTIVE`（社团已注销拒绝）
- （仅回复）父帖 `post.status != DELETED`（父帖已删除拒绝）

**负责人**路径通过 `require_leader_of_club` 校验，但仅在用户确实是某社团负责人时才透传 `NOT_CLUB_LEADER`。普通成员（非任何社团负责人）走到负责人检查失败后降级为 `FORBIDDEN`，避免向非负责人暴露 `NOT_CLUB_LEADER` 错误码：

```python
try:
    require_leader_of_club(request, post.club_id)
except ApiError as e:
    # 只对确实是某社团负责人的用户透传 NOT_CLUB_LEADER
    if e.code == "NOT_CLUB_LEADER" and ClubMembership.objects.filter(
        user=user,
        club_role=ClubMembership.ClubRole.LEADER,
        member_status=ClubMembership.MemberStatus.ACTIVE,
    ).exists():
        raise
# 否则吞掉异常，继续走到 FORBIDDEN
```

### 3. 逻辑删除，不物理删除

`post.status = Post.Status.DELETED; post.save()` 仅修改状态字段，底层数据行保留。已删除内容：
- 普通成员的帖子列表和回复列表不再返回（查询过滤 `status=NORMAL`）
- 管理员列表（`/api/admin/posts`、`/api/admin/replies`）仍然可见
- `ContentReport` 等关联引用不中断（FK 均为 `PROTECT`）

### 4. 父帖删除不级联复制

按阶段一设计，父帖删除后其回复不批量修改状态。成员查看回复时，先检查父帖状态：
- `list_replies` 检查 `post.status != DELETED`，父帖已删除则返回 `RESOURCE_DELETED`
- 回复本身保持 `NORMAL`，管理员仍可在回复列表看到它们

### 5. 路由复用而非冲突

`DELETE /api/posts/{post_id}` 与现有 `GET /api/posts/{post_id}` 路径相同。将原 `post_detail` 视图改为 `post_detail_or_delete` 方法分发：

```python
def post_detail_or_delete(request, post_id):
    if request.method == "GET":
        return post_detail(request, post_id)
    if request.method == "DELETE":
        return _delete_post(request, post_id)
    raise ApiError(...)
```

这与 `posts_list_or_create`（GET/POST）、`leader_announcement_detail`（PATCH/DELETE）的模式一致。

### 6. 学生端通过 getProfile 获取当前用户 ID

`StudentClubDetailView` 的删除按钮需要判断 `post.author.id === currentUserId`。该组件此前不使用当前用户 ID，S16 在 `onMounted` 中调用 `getProfile()` 获取：

```typescript
onMounted(async () => {
  try {
    const profile = await getProfile()
    currentUserId.value = profile.id
  } catch (_) {
    // 获取失败时删除按钮不显示
  }
  // ... 原有加载逻辑
})
```

获取失败时 `currentUserId` 保持 `null`，删除按钮自然不渲染，不影响页面正常使用。

### 7. 删除确认弹窗

所有删除操作（学生端、负责人端、管理员端）在发送请求前均弹出 `ElMessageBox.confirm`，避免误操作：

```typescript
await ElMessageBox.confirm(
  `确定要删除帖子「${post.title}」吗？删除后成员将不再可见。`,
  '确认删除',
  { confirmButtonText: '确定删除', cancelButtonText: '取消', type: 'warning' },
)
```

### 8. 前端乐观更新

删除成功后根据场景更新本地状态：
- **学生端**：从 `posts` 数组或 `repliesMap[postId]` 中移除已删除条目
- **负责人端**：将本地 `posts` 中的条目 `status` 更新为 `"已删除"`
- **管理员端**：重新调用 `loadPosts()` / `loadReplies()` 获取最新列表

## 错误码

| 错误码 | HTTP 状态 | 场景 |
|---|---|---|
| `RESOURCE_NOT_FOUND` | 404 | 帖子/回复 ID 不存在 |
| `POST_DELETED` | 409 | 帖子已删除（重复删除帖子；作者删除回复时父帖已删除） |
| `REPLY_DELETED` | 409 | 回复已删除（重复删除回复） |
| `MEMBERSHIP_INACTIVE` | 403 | 作者已退出或已被移除 |
| `CLUB_CANCELLED` | 409 | 作者所在社团已注销 |
| `NOT_CLUB_LEADER` | 403 | 负责人尝试删除其他社团内容（仅当用户是某社团负责人时返回，普通成员降级为 FORBIDDEN） |
| `FORBIDDEN` | 403 | 非作者、非负责人、非管理员的普通成员尝试删除他人内容 |
| `UNAUTHENTICATED` | 401 | 未登录 |
