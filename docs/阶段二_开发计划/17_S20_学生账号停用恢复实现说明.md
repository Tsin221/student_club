# S20：学生账号停用、恢复与最后负责人保护 — 实现说明

## 文档信息

- **切片 ID**：S20
- **用户结果**：管理员停用或恢复学生账号；系统保证任何正常社团始终至少有一名有效负责人。
- **依赖**：S05
- **状态**：已验收

## 实现范围

### 新增模型

无。`User` 模型在 S01 已包含 `account_status` 字段（`ACTIVE = "active"` / `DISABLED = "disabled"`），停用/恢复只需更新此字段，无需新增数据表或迁移。

### 现有模型利用

| 模型 | 用途 |
|------|------|
| `User` | `account_status` 字段已在 S01 定义；停用时设为 `disabled`，恢复时设为 `active` |
| `Club` | 查询正常社团（`status=normal`），已注销社团不参与最后负责人检查 |
| `ClubMembership` | 查询目标学生在正常社团中的有效负责人关系（`member_status=active, club_role=leader`） |

### 新增接口（1 个）

| 接口 | 调用者 | 说明 |
|------|--------|------|
| `PATCH /api/admin/users/{user_id}/status` | 系统管理员 | 将学生账号的 `account_status` 设为 `active` 或 `disabled`；停用时检查最后有效负责人保护 |

**请求体**：`{ "account_status": "active" | "disabled" }`，严格字段校验，不允许多余或缺失字段。

**成功响应**：`{ "user_id": <id>, "account_status": "<new_status>" }`。

### 页面修改（1 个）

| 页面 | 修改内容 |
|------|----------|
| `AdminUsersView` | 操作列增加「停用」按钮（正常状态学生，红色 `danger`）和「恢复」按钮（已停用学生，绿色 `success`）；列宽从 120 增至 180；点击弹出确认对话框，成功后刷新列表；失败时展示服务端错误消息 |

### 类型新增

| 文件 | 新增类型 |
|------|----------|
| `types/user.ts` | `UpdateUserStatusInput`（`{ account_status: "active" \| "disabled" }`）、`UpdateUserStatusResult`（`{ user_id: number, account_status: "active" \| "disabled" }`） |

### API 层新增

| 文件 | 新增函数 |
|------|----------|
| `api/auth.ts` | `updateUserStatus(userId, input)` — `PATCH` 请求 + 运行时响应校验（`user_id` 和 `account_status` 类型） |

## 关键实现决策

### 1. 不新增数据库迁移

`User.account_status` 字段在 `users.0001_initial` 迁移中已存在：

```python
class AccountStatus(models.TextChoices):
    ACTIVE = "active", "正常"
    DISABLED = "disabled", "已停用"
```

S20 只需在视图层更新此字段，无需任何迁移。

### 2. 最后有效负责人保护

停用学生前，查询该学生在所有正常社团（`club.status=normal`）中的有效负责人成员关系。对每个社团调用 `_count_other_effective_leaders(club, exclude_user)` 统计排除该学生后的有效负责人数：

```python
def _count_other_effective_leaders(club, exclude_user):
    from clubs.models import ClubMembership
    user_model = get_user_model()
    return ClubMembership.objects.filter(
        club=club,
        member_status=ClubMembership.MemberStatus.ACTIVE,
        club_role=ClubMembership.ClubRole.LEADER,
        user__account_status=user_model.AccountStatus.ACTIVE,
    ).exclude(user=exclude_user).count()
```

任一社团计数为 0 时，返回 `LAST_EFFECTIVE_LEADER`（409），整次操作不改变账号状态。

此逻辑与 S05 中 `admin_remove_leader` 的保护一致：均统计 `member_status=ACTIVE + club_role=LEADER + user__account_status=ACTIVE`。

### 3. 在 users 模块内延迟导入 ClubMembership

`_count_other_effective_leaders` 在函数体内 `from clubs.models import ClubMembership` 延迟导入，避免 `users` ↔ `clubs` 循环导入。同样，`admin_update_user_status` 视图中的停用检查也在函数体内导入 `Club` 和 `ClubMembership`。

### 4. 认证兼容（无需额外修改）

已有两个认证检查点在 S01 已覆盖停用账号的拒绝：

- **新登录**：`login_view`（`users/views.py` 第 225 行）检查 `account_status != ACTIVE` → `ACCOUNT_DISABLED`
- **已有会话**：`require_active_student`（`users/views.py` 第 110 行）检查 `account_status != ACTIVE` → `ACCOUNT_DISABLED`

S20 无需修改任何认证代码。

### 5. 停用不删除数据

`target_user.account_status = "disabled"; target_user.save(update_fields=["account_status"])` 只更新一个字段。所有成员关系、帖子、回复、评价等关联数据保持原样。

### 6. 恢复只恢复登录资格

`account_status` 恢复为 `active` 后，不修改任何成员关系状态或社团身份。学生恢复后可以正常登录，但其在社团中的角色和状态由社团管理操作独立决定。

### 7. 停用已注销社团的负责人不阻止

已注销社团（`club.status=CANCELLED`）的负责人关系不参与最后负责人检查。停用这样的学生不会触发 `LAST_EFFECTIVE_LEADER`。这与 S05 移除负责人时只允许操作正常社团的逻辑一致。

### 8. 幂等性

请求的 `account_status` 与当前状态相同时，直接返回成功（含 `"账号状态未变更"` 消息），不产生数据库写入。

### 9. 前端确认弹窗

停用操作弹出 `ElMessageBox.confirm`（`type="warning"`），明确提示"停用后该账号将无法登录，已有会话也会被拒绝"。恢复操作同样弹窗确认（`type="info"`）。`LAST_EFFECTIVE_LEADER` 等错误通过 `ElMessage.error` 显示服务端返回的中文消息。

## 错误码

| 错误码 | HTTP 状态 | 场景 |
|--------|-----------|------|
| `UNAUTHENTICATED` | 401 | 未登录 |
| `FORBIDDEN` | 403 | 非管理员调用 |
| `RESOURCE_NOT_FOUND` | 404 | 目标用户 ID 不存在 |
| `NOT_STUDENT_USER` | 422 | 目标是管理员账号 |
| `INVALID_REQUEST` | 400 | 请求体字段缺失/多余/非 PATCH 方法 |
| `VALIDATION_ERROR` | 422 | `account_status` 不是 `active` 或 `disabled` |
| `LAST_EFFECTIVE_LEADER` | 409 | 停用会导致某个正常社团失去最后一名有效负责人 |

## 迁移

无新增迁移。`User.account_status` 字段在 `users.0001_initial` 已建立。
