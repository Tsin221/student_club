## 2. S04 的目标

S04 建立社团与成员关系的核心数据结构，使系统管理员可以：

1. 从正常学生中指定至少一名初始负责人创建社团（含 Logo 上传）。
2. 在管理员工作台查看全部社团（正常和已注销）。
3. 学生可以在"社团广场"浏览所有正常社团并查看详情。
4. 初始负责人可以在"我的社团"看到负责人身份。

## 3. 已完成的内容

### 3.1 新建 Django 应用 `clubs`

在 `code/backend/clubs/` 下新建完整应用，包含两个核心模型。

**`Club` 模型**（表名 `club`）：
| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | `BigAutoField` PK | |
| `name` | `CharField(100) unique` | 社团唯一名称 |
| `category` | `CharField` 固定枚举 | 文化艺术/体育竞技/学术科技/公益实践/兴趣爱好/其他 |
| `introduction` | `TextField` | 社团简介 |
| `logo` | `CharField(255)` | Logo 文件路径（`logos/xxx.png`） |
| `created_at` | `DateTimeField auto_now_add` | 创建时间 |
| `status` | `CharField` 固定枚举 | 正常/已注销 |

**`ClubMembership` 模型**（表名 `club_membership`）：
| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | `BigAutoField` PK | |
| `user` | FK → `User` PROTECT | 成员用户 |
| `club` | FK → `Club` PROTECT | 所属社团 |
| `member_status` | `CharField` 固定枚举 | 在社/已退出/已移除 |
| `club_role` | `CharField` 固定枚举 | 负责人/普通成员 |

联合唯一约束 `(user, club)`，确保同一用户与同一社团只有一条成员关系。

### 3.2 后端 API 接口

新增 5 个接口：

| 方法与路径 | 用途 | 关键行为 |
|---|---|---|
| `POST /api/admin/clubs` | 管理员创建社团 | multipart/form-data；Logo 必填上传；事务中创建 Club + ClubMembership |
| `GET /api/admin/clubs` | 管理员查看全部社团 | 分页，含已注销 |
| `GET /api/clubs` | 公开社团列表 | 分页，只返回正常社团，支持按类别筛选 |
| `GET /api/clubs/{club_id}` | 社团详情 | 学生只能看正常社团（已注销→404）；管理员可看全部 |
| `GET /api/me/memberships` | 我的社团成员关系 | 返回当前和历史所有成员关系 |

**错误码**：`CLUB_NAME_EXISTS`(409)、`INVALID_CLUB_CATEGORY`(422)、`LOGO_REQUIRED`(400)、`INITIAL_LEADER_REQUIRED`(400)、`INITIAL_LEADER_INVALID`(422)

## 7. 关键决定及原因

### 7.1 `admin_clubs` 视图方法分发

`GET /api/admin/clubs` 和 `POST /api/admin/clubs` 共享同一 URL，在 `admin_clubs` 视图中按 `request.method` 分发到 `_admin_list_clubs` 和 `_admin_create_club`。

### 7.2 Logo 上传与存储

Logo 通过 `multipart/form-data` 上传，保存到 `media/logos/`，使用 UUID 生成唯一文件名。`create_admin` 命令不使用 multipart，单独处理文件。

### 7.3 leader_user_ids 以 JSON 字符串传输

创建社团时，`leader_user_ids` 在 multipart form 中以 JSON 字符串传输（如 `[1, 2]`），后端解析后校验去重。

## 8. 已知限制
