## 2. 切片执行规则

### 2.1 什么是一个切片

一个切片必须贯穿完成该用户路径所需的最小数据库、后端、前端和测试工作。仅完成数据表、仅完成接口或仅完成页面，都不能算作切片完成。

每个切片必须满足：

- 有一个可以从页面入口实际完成的用户目标。
- 只引入完成该目标所需的字段、接口和页面。
- 同时覆盖正常路径、主要权限拒绝和关键业务错误。
- 完成后项目仍可启动、可构建、可测试。
- 可以独立演示，并能说明该切片没有依赖未完成页面才能成立。

### 2.2 状态定义

每个切片只能使用以下状态：

- `未开始`：尚未写入该切片的实现代码。
- `进行中`：正在实现，尚未满足全部验收条件。
- `待验收`：实现和自动检查完成，等待端到端验收。
- `已验收`：所有勾选项通过，验收记录完整。
- `阻塞`：存在无法由当前开发者自行解决的外部决定或环境问题。

同一时间只允许一个业务切片处于 `进行中`。S00 完成后，每次开始下一片前先确认其依赖切片均已验收。

### 2.3 每片固定工作循环

1. 将切片状态改为 `进行中`，记录开始日期。
2. 先补该切片的失败测试或可验证失败条件。
3. 完成最小实现，不顺手实现后续切片。
4. 运行该切片测试、已有回归测试、后端检查和前端构建。
5. 在浏览器中走通完整用户路径和主要异常路径。
6. 填写迁移、提交、验证结果和遗留问题。
7. 全部通过后改为 `已验收`，再开始下一片。

### 2.4 全局完成标准

任何业务切片只有同时满足以下条件才能标记为 `已验收`：

- [ ] 数据库迁移可以从空数据库执行。
- [ ] 新增接口遵守 `code`、`message`、`data` 统一包装。
- [ ] 列表接口遵守 `page`、`page_size`、`items`、`page`、`page_size`、`total`。
- [ ] 后端不信任前端提交的当前用户、角色、状态、所属社团或系统时间。
- [ ] 前端隐藏按钮不替代后端权限校验。
- [ ] 后端测试通过。
- [ ] 前端构建通过。
- [ ] 浏览器端到端路径通过。
- [ ] 没有把密码、Session、DeepSeek 密钥或其他秘密写入代码、日志或版本库。
- [ ] 没有加入该切片范围外的功能。
- [ ] 验收记录已经填写。
