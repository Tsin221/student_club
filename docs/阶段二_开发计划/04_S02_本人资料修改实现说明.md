## 2. S02 的目标

S02 建立学生修改本人资料的垂直路径，使已登录学生可以：

1. 在 `/student` 个人中心看到"编辑资料"入口。
2. 进入 `/student/profile/edit`，表单预填当前姓名、手机号、专业班级和年级。
3. 修改一个或多个允许字段并提交保存。
4. 保存成功后返回个人中心，立即看到更新后的资料。
5. 系统拒绝修改用户名、平台角色、账号状态、注册时间等系统字段。

本切片只涉及一个已有接口的方法扩展和一个新页面，不增加其他业务能力。

## 3. 已完成的内容

### 3.1 后端资料修改接口

`PATCH /api/me/profile` 与现有 `GET /api/me/profile` 共用同一 URL，按请求方法分发：

| 方法与路径 | 用途 | 关键行为 |
|---|---|---|
| `GET /api/me/profile` | 读取本人资料 | 与 S01 行为完全一致，无变化 |
| `PATCH /api/me/profile` | 修改本人资料 | 只接受 `name`、`phone`、`major_class`、`grade` 中至少一个可选字段；更新并返回 `SelfUser` |

PATCH 请求的字段规则：

- 允许提交的字段：`name`、`phone`、`major_class`、`grade`。
- 必须提交至少一个字段。
- 每个字段值必须是字符串，去除首尾空白后不能为空。
- 提交 `username`、`platform_role`、`account_status`、`registered_at` 或头像相关字段返回 `INVALID_REQUEST`。
- 各字段长度限制与注册一致：姓名 ≤ 50、手机号 ≤ 20、专业班级 ≤ 100、年级 ≤ 20。

权限校验顺序：

1. 用户已登录 → 否则 `UNAUTHENTICATED`（401）。
2. 账号状态为正常 → 否则 `ACCOUNT_DISABLED`（403）。
3. 平台角色为学生 → 否则 `FORBIDDEN`（403）。

### 3.2 前端请求层扩展

在 `src/api/auth.ts` 中新增 `updateProfile` 函数：

- 使用 `PATCH` 方法发送 JSON 请求体。
- 请求体只包含调用方传入的允许字段，不额外附加系统信息。
- 统一解包 `code`、`message`、`data`，非成功响应转换为 `ApiRequestError`。
- 成功响应中的用户资料再次执行 `isSelfUser` 运行时结构检查。

### 3.3 类型定义

在 `src/types/user.ts` 中新增 `ProfileUpdateInput` 接口：

```typescript
export interface ProfileUpdateInput {
  name?: string
  phone?: string
  major_class?: string
  grade?: string
}
```

四个字段均为可选，但调用方必须至少传入一个。

### 3.4 编辑资料页面

新增路由 `/student/profile/edit`，对应 `StudentProfileEditView.vue`：

- 页面加载时调用 `GET /api/me/profile` 获取当前资料并预填表单。
- 表单包含姓名、手机号、专业班级、年级四个输入框，均带有明确标签和 `autocomplete` 属性。
- 提交前执行前端校验：至少修改一个字段、去除空白后不为空、不超过长度限制。
- 保存中显示加载状态并禁用按钮，防止重复提交。
- 保存成功跳回 `/student` 并显示成功提示。
- 保存失败保留已填写的表单内容，显示后端返回的错误信息。
- 未登录、账号停用或非学生账号访问时跳回 `/login` 并显示对应原因。
- 页面左上角显示"← 返回个人中心"链接。

### 3.5 个人中心编辑入口

在 `/student` 页面的资料卡片右上角增加"编辑资料"按钮（使用 Element Plus `el-button`，`type="primary"` 的朴素变体 `plain`），点击后导航至 `/student/profile/edit`。

## 8. 关键决定及原因

### 8.1 GET 和 PATCH 共用同一 URL 路径

遵循阶段一 API 设计中 `GET /api/me/profile` 和 `PATCH /api/me/profile` 共用路径的决定。视图函数内按 `request.method` 分发，避免 URL 配置冲突。

### 8.2 只允许修改四个字段

严格遵循阶段一权限矩阵"学生可维护资料仅限姓名、手机号、专业班级和年级"的规则。用户名、平台角色、账号状态和注册时间由系统控制。

### 8.3 保存失败保留表单内容

如果后端校验失败，前端保留用户已输入但尚未提交成功的表单内容，避免用户因为一个字段错误而重新填写所有字段。

### 8.4 不增加需求外功能

没有增加修改密码、修改用户名、更换头像或上传头像入口，也没有增加退出登录或注销账号功能。

## 9. 已知限制

1. Element Plus 仍按 S00 方式全量引入，生产构建存在大于 500 kB 的包体积警告。
2. 本切片按设计不提供头像上传、修改密码或用户名修改。
3. 手机号格式不做正则校验（阶段一未要求，由学校自行决定格式策略）。
