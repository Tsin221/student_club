## 1. 设计边界

### 1.1 页面入口

1. 系统不设置独立前台首页。
2. 未登录用户只能进入登录页和注册页。
3. 系统管理员登录成功后进入管理员工作台。
4. 学生登录成功后进入学生个人中心，再进入社团公开页面或本人有权访问的社团内部页面。
5. 学生进入本人负责的社团时，普通成员菜单继续保留，并额外显示负责人管理菜单。
6. 已注销社团只出现在学生的历史社团记录和管理员历史数据中，不向学生展示社团内部菜单。

### 1.2 第一版界面约束

- 页面以白色为主，蓝色作为主要点缀色。
- 使用 Element Plus 的基础布局、表格、表单、统计卡片、对话框和抽屉即可。
- 不提供深色模式、主题切换、额外动画或专门的移动端适配。
- 数据概览只使用数字统计卡片，不使用趋势图、排行榜、评分图或其他复杂图表。
- 社团 Logo 按既有字段展示；用户统一使用默认头像，不提供头像上传入口。
- 公告和帖子第一版只使用纯文本标题和正文，不出现图片或附件字段。
- 创建、修改、查看详情和处理操作尽量放在列表页的对话框或抽屉中，不为简单操作增加独立路由。

### 1.3 页面与权限原则

- 菜单隐藏只负责减少无效入口，后端仍按 `01_角色权限矩阵.md` 强制校验。
- 前端不能根据本地保存的角色信息直接认定有权限；进入页面后仍以接口返回结果为准。
- 学生社团内部页面必须满足账号正常、社团正常、成员状态为在社。
- 负责人页面在上述条件基础上，还必须满足当前社团身份为负责人。
- 系统管理员依据平台角色访问管理员页面，不要求具有社团成员关系。
- 访问无权页面时不展示目标数据，提示无权访问并返回该角色默认入口。
- 前端不保存 Bearer Token；浏览器自动携带 Django 会话 Cookie。首次提交写请求前调用 `GET /api/auth/csrf` 初始化令牌，之后的 `POST`、`PATCH`、`DELETE` 请求按后端约定附带该令牌。
- 所有接口先按 `code`、`message`、`data` 解包；成功业务数据读取 `data`，失败统一显示 `message` 并按错误码处理页面状态。
- 所有列表页面使用 `page`、`page_size` 请求和 Element Plus 分页组件，读取 `data.items`、`data.page`、`data.page_size`、`data.total`；默认每页 20 条，最多 100 条。

## 2. 路由入口与守卫

### 2.1 根路由跳转

| 当前状态 | 访问 `/` 的结果 |
|---|---|
| 未登录 | 跳转 `/login` |
| 已登录系统管理员 | 跳转 `/admin` |
| 已登录学生 | 跳转 `/student` |

### 2.2 路由守卫

| 路由范围 | 前端进入条件 | 接口再次校验 | 失败行为 |
|---|---|---|---|
| `/login`、`/register` | 未登录 | 登录或注册接口执行校验 | 显示接口错误；已登录时跳转到对应工作台 |
| `/student/**` | 已登录学生 | 学生受保护接口校验账号状态 | 账号已停用时停止展示业务数据，提示账号已停用并返回登录页 |
| `/student/clubs/:clubId/inside/**` | 学生路由条件成立 | 校验社团正常、成员在社 | 已注销时进入历史社团提示；非成员、已退出或已移除时返回“我的社团” |
| `/student/leader/:clubId/**` | 学生路由条件成立，菜单中存在对应负责社团 | 校验社团正常、成员在社、社团身份为负责人 | 无负责人权限时返回学生个人中心；社团已注销时返回历史社团 |
| `/admin/**` | 已登录系统管理员 | 管理员接口校验平台角色 | 无管理员权限时不展示数据并返回对应角色默认入口 |

前端守卫不单独建立权限表，也不以本地存储值判断登录状态；以会话 Cookie 对本人资料和本人成员关系接口的实际请求结果控制菜单。接口返回 `UNAUTHENTICATED` 时清空页面内存状态并跳转登录页，其他接口拒绝结果也优先于前端已有状态。

### 2.3 当前社团上下文

- 普通成员从“我的社团”选择社团后，路由中的 `:clubId` 表示当前社团。
- 负责人工作台顶部提供“当前负责社团”选择框，数据来自 `GET /api/me/memberships` 中社团正常、成员在社且身份为负责人的关系。
- 切换负责社团时只替换路由中的 `:clubId` 并重新请求当前页面数据，不在前端混用不同社团的数据。
- 如果路由中的 `clubId` 不属于当前学生负责范围，不显示负责人页面内容。

## 4. 通用页面状态

页面表格中的状态行为均按以下规则实现：

- **空状态**：显示简短空提示和页面已有的允许操作，不虚构示例数据。
- **加载状态**：列表或卡片显示基础加载状态；提交期间禁用当前提交按钮，避免重复提交。
- **错误状态**：显示后端返回的明确提示；读取失败时提供重新加载，写入失败时保留用户尚未成功提交的表单内容。
- **已注销社团**：学生不能进入公开申请或内部业务；从内部路由返回“我的社团”的历史记录。管理员仍可在管理页面查看历史。
- **已删除内容**：普通成员不展示已删除公告、帖子和回复；负责人只在既有内容管理或举报处理场景查看本社团已删除内容；管理员可在内容管理中查看已删除帖子和回复。
- **无权访问**：不展示目标数据，提示无权访问并返回当前角色可访问的默认页面。对其他社团内部资源可统一显示“内容不存在或无权访问”。

## 11. 已确认的页面实现约定

以下事项由用户于 2026-07-28 确认，并与 `05_API接口设计.md` 保持一致：

1. 使用 Django Session、`HttpOnly` Cookie 和 CSRF；前端不保存 Bearer Token。
2. 响应统一使用 `code`、`message`、`data`；列表使用 `page`、`page_size` 和 `items`、`page`、`page_size`、`total`。
3. 社团名称唯一；管理员创建或修改社团时显示重名字段错误。
4. 帖子标题最多 255 字、正文最多 5000 字、回复内容最多 1000 字，页面与服务端使用相同字符上限。
5. DeepSeek 模型名和请求参数由后端环境配置；页面不提供选择控件。
6. 负责人概览的帖子数量只统计正常帖子。
7. “最新帖子”以自增 ID 倒序表示；置顶帖子优先，同组内按 ID 倒序。

以下边界不因上述决定改变：

- 公告和帖子图片属于时间允许再完善，本版表单不出现对应字段。
- 不增加帖子发布时间、前端模型配置或新的统计图表。
