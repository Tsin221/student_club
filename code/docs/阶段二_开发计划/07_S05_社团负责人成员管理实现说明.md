## 2. S05 的目标

S05 在 S04 的基础上增加社团和成员管理的完整能力：

1. **管理员**可修改社团信息（名称/类别/简介）、注销社团、增删负责人、查看全量成员关系。
2. **负责人**可修改本人负责社团的简介，查看当前在社成员列表（含手机号）。
3. 建立负责人"当前社团上下文"机制——通过 URL 携带 clubId 实现路由、数据和 API 的同步。

## 3. 已完成的内容

### 3.1 后端新增

#### 守卫函数

- **`require_leader_of_club(request, club_id)`**：依次校验认证状态、学生身份、账号正常、社团存在且正常、成员在社且身份为负责人。返回 `(user, membership)`。

- **`_count_effective_leaders(club)`**：统计正常社团的有效负责人数量（账号正常+在社+负责人身份）。

#### 请求体解析辅助

- **`_parse_json_body(request)`**：安全解析 JSON 请求体。
- **`_parse_club_patch_body(request, allowed_fields)`**：自动检测 `multipart/form-data` 或 `application/json`，提取文本字段和可选 Logo 文件。对于 PATCH 方法的 multipart 请求，使用 Django 的 `MultiPartParser` 手动解析（Django 只对 POST 自动解析 multipart）。

#### 7 个新接口

| 方法与路径 | 用途 | 关键行为 |
|---|---|---|
| `PATCH /api/admin/clubs/{club_id}` | 管理员修改社团 | 可选修改 name/category/introduction；名称唯一校验；类别枚举校验 |
| `POST /api/admin/clubs/{club_id}/cancel` | 管理员注销社团 | 已注销返回 CLUB_ALREADY_CANCELLED(409) |
| `PATCH /api/leader/clubs/{club_id}` | 负责人修改简介 | 只允许 introduction；拒绝 name/category 等字段 |
| `GET /api/admin/memberships` | 管理员查看全量成员关系 | 分页，含所有状态 |
| `GET /api/leader/clubs/{club_id}/members` | 负责人查看在社成员 | 含手机号（符合设计）；只返回在社成员 |
| `POST /api/admin/clubs/{club_id}/leaders` | 管理员提升负责人 | 校验在社+普通成员+账号正常 |
| `DELETE /api/admin/clubs/{club_id}/leaders/{membership_id}` | 管理员降级负责人 | 执行最后有效负责人保护 |

#### 新增错误码

| 错误码 | HTTP | 说明 |
|--------|------|------|
| `CLUB_ALREADY_CANCELLED` | 409 | 社团已注销 |
| `NOT_CLUB_LEADER` | 403 | 非目标社团当前有效负责人 |
| `MEMBERSHIP_NOT_ACTIVE` | 422 | 成员关系不在社 |
| `MEMBERSHIP_NOT_ORDINARY` | 422 | 目标不是普通成员 |
| `NOT_CURRENT_LEADER` | 422 | 目标不是负责人 |
| `LAST_EFFECTIVE_LEADER` | 409 | 不能移除最后一名有效负责人 |

#### 序列化器

- **`serialize_membership_for_leader(membership)`**：负责人视角的成员信息，包含完整 user 资料（含手机号）和 `club_id`。

## 6. 关键决定及原因

### 6.1 PATCH multipart 手动解析

Django 只对 POST 请求自动解析 `multipart/form-data` 请求体。对于 PATCH 请求的 Logo 文件上传，使用 Django 的 `MultiPartParser` 手动解析请求体。Logo 只能通过文件上传更新，不支持 JSON 文本路径传递。

### 6.2 管理员加载成员列表的策略

`AdminClubDetailView.vue` 使用 `GET /api/leader/clubs/{club_id}/members` 获取在社成员进行负责人管理。这是因为管理员本身没有成员关系，但需要查看在社成员名单来增删负责人。该接口在负责人上下文中返回手机号——这是设计允许的（管理员在其他接口中也能查看手机号）。

### 6.3 Leader workspace 单页设计

负责人工作台使用单页设计（编辑 + 成员列表），而非多子页面。这减少了路由复杂度，且 S05 的负责人功能有限（只编辑简介和查看成员）。

## 7. 已知限制

1. **PATCH multipart Logo 上传**：Django test client 不支持 PATCH multipart，Logo 文件上传的端到端测试仅在浏览器中进行。JSON 文本字段更新测试完整覆盖。
2. Element Plus 全量引入仍有包体积警告。
3. 管理员编辑社团时暂无 Logo 上传的前端 UI（Logo 上传通过文件接口待 S05+浏览器验收时补充）。
